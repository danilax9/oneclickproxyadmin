# Proxy Panel

Лёгкая self-hosted веб-панель для управления HTTP/HTTPS-прокси и их
пользователями на сервере. Один Docker-контейнер: FastAPI-бэкенд +
SQLite + [3proxy](https://github.com/3proxy/3proxy) в качестве
прокси-движка, тёмный веб-интерфейс без сборки фронтенда.

## Возможности

- Авторизация в панель по паролю (`ADMIN_PASSWORD`).
- Автоопределение внешнего IP сервера.
- Открытие/удаление прокси-портов (HTTP или HTTPS-туннелирование через CONNECT).
- Создание пользователей (логин/пароль вручную или автогенерация), привязка к портам.
- Готовые ссылки вида `http://user:password@SERVER_IP:PORT` с копированием в буфер.
- Блокировка и удаление пользователей.
- Изменения применяются "на лету" (реген конфига 3proxy + reload) без обрыва
  прочих активных соединений.

## Быстрый старт

```bash
git clone <ваш-репозиторий> proxy-panel
cd proxy-panel
cp .env.example .env
# отредактируйте .env — обязательно смените ADMIN_PASSWORD
docker-compose up -d --build
```

Панель будет доступна на `http://<IP_СЕРВЕРА>:8000` (порт задаётся
переменной `PANEL_PORT`).

## Почему `network_mode: host`

Компоуз-файл использует host-сеть, чтобы прокси-порты, которые вы
открываете прямо из веб-интерфейса (например, 3128, 8080, 8443...),
сразу становились доступны на сервере — без необходимости заранее
прописывать каждый порт в `docker-compose.yml` и пересобирать контейнер.

Если host-режим вам не подходит (например, разворачиваете внутри
уже изолированной сети), уберите `network_mode: host`, пробросьте
`PANEL_PORT` через `ports:` и добавьте туда же диапазон нужных
прокси-портов вручную.

## Переменные окружения

| Переменная       | Обязательна | Описание                                           |
|------------------|-------------|-----------------------------------------------------|
| `ADMIN_PASSWORD` | да          | Пароль для входа в панель                           |
| `PANEL_PORT`     | нет         | Порт веб-интерфейса (по умолчанию `8000`)           |
| `SECRET_KEY`     | нет         | Ключ для подписи сессионных cookie (см. `.env.example`) |

## Хранение данных

Все данные (SQLite база и конфиг 3proxy) лежат в volume `proxy-data`,
логи прокси — в `proxy-logs`. При пересоздании контейнера
(`docker-compose up -d --build`) пользователи и порты сохраняются.

## Как это работает внутри

- FastAPI-приложение — единственный процесс, который слушает контейнер
  на старте (`uvicorn`), само поднимает `3proxy` как дочерний процесс.
- При любом изменении портов/пользователей панель перегенерирует
  конфиг 3proxy и посылает процессу сигнал на релоад конфигурации;
  если процесс почему-то не отвечает — происходит быстрый рестарт.
- HTTP и HTTPS для конечного пользователя не различаются на уровне
  3proxy: один и тот же `proxy`-сервис обслуживает и обычный HTTP, и
  HTTPS через метод `CONNECT` (стандартное поведение HTTP-прокси).
  Тип порта в интерфейсе — это, по сути, пометка для вас самих /
  для генерации ссылки нужной схемы.

## Разработка без Docker

```bash
python3 -m venv venv && source venv/bin/activate
pip install -r requirements.txt
export ADMIN_PASSWORD=test123
# для локальной разработки без реального 3proxy можно подставить заглушку:
export THREEPROXY_BIN=/bin/true
uvicorn app.main:app --reload
```

## Безопасность

- Обязательно смените `ADMIN_PASSWORD` перед деплоем.
- Рекомендуется поставить перед панелью reverse-proxy с HTTPS (Caddy,
  nginx, Traefik) — сама панель отдаёт только HTTP.
- Cookie сессии помечены `httponly`.
